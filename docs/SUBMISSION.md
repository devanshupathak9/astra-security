## 1. The repo

**What it is.** The full pipeline: ingest an APK → scan with a model → teacher writes lessons →
student scans again → measure recall. Everything runs with one command.

**How to run it**
```bash
./setup.sh                 # one time: Python deps, Java + jadx, sample APK, .env
./run_all.sh --free        # whole experiment on Groq's free tier (open models)
./run_all.sh               # same, with the models set in .env (e.g. OpenAI)
./run_all.sh --app x.apk   # on a different app
```

**What to read first:** `README.md` (how to run), `docs/architecture.md` (how it works).

**What you do:** share the link → https://github.com/devanshupathak9/astra-security

## 3. The open model's recall before and after the lessons

**What it is.** `./run_all.sh` runs the experiment and writes the numbers to
`runs/<time>/report.md`, copied to `docs/results.md`:

- **before** – student scans with no help
- **placebo** – student gets generic advice of the same length (control: is it just a longer prompt?)
- **after** – student gets the teacher's lessons
- **lift** – after minus before (the headline), and after minus placebo

Two recall numbers: **strict** (right file and right bug type) and **lenient** (right file).

**Result (already in `docs/writeup.md` section 1):** open student `gpt-oss-20b`, strict recall
**68% → 74% after lessons (+5 pts, +1 bug)**; placebo stayed at 68%. Lenient recall 95% → 95%.

**What you do:** put the headline in your email, e.g.
"Open student (gpt-oss-20b) strict recall 68% → 74% with the teacher's lessons (+5 pts);
a same-length placebo stayed at 68%, so the gain came from the lessons' content."

## 4. Optional: frontier scan on one real APK

**What it is.** Scan a real-world app (no answer key) and check each finding by hand: real bug or noise.

**What you do (≈1 hour)**
1. Download an open-source app's APK (e.g. from F-Droid) into `apks/`.
2. `python main.py scan --model teacher --app apks/<app>.apk`
3. Open the findings file it prints; mark each finding real / noise by reading the quoted code.
4. Write 3–5 lines in section 6 of the doc: N findings, X real, Y noise, what broke.

Skip it if short on time – it's optional.
